# 飞书客服业务任务量登记与报表系统

## 概述

通过飞书 WebSocket 长连接接收群聊消息，自动识别消息类型并登记到飞书多维表格（Bitable），支持跨月查询、修改删除、定时提醒，并以**飞书互动卡片消息（JSON 2.0）**形式生成含内嵌可视化图表的日报/周报/月报。

运行环境：`server.py`（主程序，~1350 行），Python 3.12，lark-oapi SDK v1.6.6。

## 数据表结构

每月在同一个 Base 中创建两张表（按月归档，通过 `.state_YYYY-MM.json` 跟踪）。

### 表1：IM会话量(拼多多+千牛+抖音)

| 字段 | 类型 | 说明 |
|------|------|------|
| 日期 | 日期（毫秒时间戳） | 登记日期 |
| 姓名 | 文本 | 从飞书消息发送者自动获取 |
| 拼多多火车票 | 数字 | 拼多多-火车票会话量 |
| 拼多多机票 | 数字 | 拼多多-机票会话量 |
| 千牛 | 数字 | 千牛平台会话量 |
| 抖音 | 数字 | 抖音平台会话量 |
| 合计 | 数字 | 四平台之和，自动计算 |
| 备注 | 文本 | 可选 |

### 表2：火车票分销群聊登记表

| 字段 | 类型 | 说明 |
|------|------|------|
| 日期 | 日期（毫秒时间戳） | 登记日期 |
| 姓名 | 文本 | 发送者姓名 |
| 订单号 | 文本 | 订单编号 |
| 备注 | 文本 | 可选 |

## 消息分类与路由

`classify_message()` 按以下优先级分类：

| 优先级 | 规则 | 触发关键词 | 路由 |
|--------|------|------------|------|
| 1 | 报表 | "日报"/"周报"/"月报"/"报表" | `handle_report` → 返回卡片消息 |
| 2 | 提醒 | "提醒"/"催一下"/"上报" | `handle_remind` |
| 3 | 修改/删除 | "修改"/"改一下"/"删除"/"删掉"/"去掉" | `handle_modify` / `handle_delete` |
| 4 | 查询 | "查询"/"统计"/"排名"/"占比"等 | `handle_query` |
| 5 | 平台会话登记 | "拼多多火车票"+数字、"千牛"+数字等正则匹配 | `handle_register` → 表1 |
| 6 | 订单号登记 | HT开头、纯数字6位以上 | `handle_register` → 表2 |
| 7 | 未知 | — | 返回帮助文本 |

## 核心功能

### 1. 数据登记

解析消息中的平台会话量（正则表达式提取四个平台的数值，自动计算合计）或订单号列表（支持逗号/空格/换行分隔，过滤 @提及），写入当月对应的飞书多维表格。返回引用回复确认。

### 2. 跨月查询

- **个人查询**（默认）：汇总所有历史月份数据，按月份展示明细
- **排名**：全部历史数据按合计排序，TOP3 金银铜牌
- **平台占比**：四平台累计值和百分比

通过扫描 `.state_*.json` 文件实现跨月聚合。

### 3. 修改与删除

- **修改格式**：`修改 <关键词> <字段>=<新值>` — 在两张表中模糊搜索匹配记录，批量更新
- **删除格式**：`删除 <关键词>` — 模糊搜索后按表分组，调用飞书批量删除 API

### 4. 定时提醒

后台线程每 30 秒检查，在 **14:55**（白班结束）和 **23:55**（晚班结束）向所有已知群聊发送上报提醒。

### 5. 报表系统（飞书卡片消息）

三个报告方法均以**飞书互动卡片（JSON 2.0）**形式返回，图表内嵌在卡片中。卡片发送失败时自动降级为文本 + 单独图片消息。

#### 日报
- 昨日每人各平台会话量 + 订单数
- 平台合计
- **7天趋势折线图**（标注最高/最低点）
- 卡片 header 颜色：`blue`

#### 周报
- 上周每人汇总（含日均和 🥇🥈🥉 排名）
- 平台合计
- **环比变化率**（与上上周对比，↑X% / ↓X% / →持平）
- **排名柱状图**（TOP10，前三名金银铜高亮）
- **平台占比饼图**（四平台百分比）
- 订单汇总
- 卡片 header 颜色：`turquoise`

#### 月报
- 上月每人汇总（含日均和奖牌排名）
- 平台合计 + 占比百分比
- **环比变化率**（与上上月对比）
- **排名柱状图**（TOP10）
- **平台占比饼图**
- **每日趋势折线图**（当月每天总量变化）
- 订单汇总
- 卡片 header 颜色：`purple`

### 6. 查询 open_id

消息包含 "查ID"/"我的id"/"myid"/"id" 时，直接返回发送者的 `open_id` 和当前姓名（用于配置 `name_map.json`）。

## 卡片消息系统

### 卡片构建组件（MessageHandler 方法）

| 方法 | 输出 | 用途 |
|------|------|------|
| `_make_card(title, color, elements)` | card dict | 卡片外层框架（schema: 2.0, header, body） |
| `_md(content)` | markdown 元素 | 文本块 |
| `_hr()` | 分隔线元素 | 区块分隔 |
| `_note(content)` | markdown 元素 | 脚注（带 `---` 分隔线） |
| `_img(image_key, alt)` | 图片元素 | 内嵌图表，`scale_type: fit_horizontal` |
| `_upload_chart_for_card(path)` | image_key str | 上传图表 PNG 到飞书，返回 image_key |

### 卡片发送流程

1. 报告方法计算数据、生成图表（`chart_gen.py`）、调用 `_upload_chart_for_card()` 上传获取 image_key
2. 构建卡片 JSON → 存入 `self._pending_card`
3. 事件回调检测 `_pending_card`，优先调用 `reply_card()` / `send_card()`
4. 若 API 返回错误码，降级：先发文本再发单独图片

### FeishuClient 消息方法

| 方法 | 用途 |
|------|------|
| `reply_message(msg_id, content)` | 文本引用回复 |
| `send_message(chat_id, content)` | 文本群聊消息 |
| `reply_card(msg_id, card_dict)` | 卡片引用回复（`msg_type: interactive`） |
| `send_card(chat_id, card_dict)` | 卡片群聊消息 |
| `upload_image(file_path)` | 上传图片获取 `image_key` |
| `reply_image(msg_id, image_key)` | 图片附件回复 |
| `send_image(chat_id, image_key)` | 图片群聊消息 |

## 用户名解析

三级优先级：
1. `name_map.json` — 手动维护的 `open_id → 中文名` 映射（支持热加载，无需重启）
2. 飞书通讯录 API（`contact/v3/users/{open_id}`）
3. 降级显示：外部用户（41050 错误）→ `外部用户_{open_id后4位}`，其他 → `用户_{open_id后4位}`

## 关键设计决策

- **编码**：`add_records` 使用 `data=json.dumps(body, ensure_ascii=False).encode("utf-8")` 发送原始 UTF-8 字节，避免中文姓名在 HTTP 传输中被错误编码
- **日期**：飞书日期字段存储毫秒时间戳（类型 5），通过 `_ts_to_date()` 转换为 `YYYY-MM-DD` 字符串进行比较
- **去重**：消息 ID 持久化到 `.processed_ids.json`，保留最近 5000 条，重启不丢失
- **多表删除**：`handle_delete` 按 `table_id` 分组后再调用 `delete_records`，因为飞书 API 要求同批记录必须在同一张表
